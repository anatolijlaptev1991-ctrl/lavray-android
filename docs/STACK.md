# Выбор стека LAVRay для Android

Записка для владельца и будущих разработчиков. Решение принято по трём постулатам: оптимизация, дизайн, функциональность.

## Решение

| Слой | Выбор |
|---|---|
| Интерфейс | Нативный Kotlin + Jetpack Compose, собственные компоненты поверх токенов LAVRay Design System |
| Ядро | То же ядро LAVRay на Go (`lavray/core`, тег закреплён субмодулем), собранное `gomobile bind` в `.aar` |
| Связь интерфейса и ядра | Тот же контракт `proto/lavray.proto`: Connect JSON поверх unix-сокета в приватном каталоге приложения, с токеном |
| Процессы | `main` — только интерфейс, `:vpn` — `VpnService` и ядро |
| Туннель | `VpnService` → файловый дескриптор передаётся ядру через интерфейс платформы; пакеты не пересекают JNI |

## Почему не WebView с `ui/`

`ui/` рассчитан на окно с мышью и наведением. В WebView он дал бы готовые экраны, но движок браузера заметно дороже по памяти и времени запуска, а на телефоне всё равно пришлось бы переделывать раскладку. Постулат «оптимизация» важнее экономии на написании экранов.

Наследственность сохраняется там, где она видна пользователю: те же токены цвета и движения, знак «Отражение», те же пять разделов, те же строки (словари `ui/src/lib/dictionaries` конвертируются в ресурсы Android скриптом `tools/i18n`), тот же API и та же логика в ядре.

## Почему два процесса

- Интерфейс не загружает библиотеку ядра, поэтому его холодный старт не платит за неё.
- После закрытия экрана система может выгрузить процесс интерфейса вместе с Compose, а в памяти при работающем VPN остаётся только `:vpn`.
- Хранилище открыто одним процессом, поэтому межпроцессных блокировок SQLite нет.

Цена: при открытом интерфейсе работают две виртуальные машины. Этот режим короткий, основное время телефон проводит с закрытым экраном приложения.

## Почему ядро встраивается, а не запускается отдельным исполняемым файлом

`VpnService.protect()` и передача дескриптора работают напрямую внутри процесса. Отдельный бинарник потребовал бы передачу дескрипторов через сокет и ещё один процесс.

## Как ядро остаётся неизменным

Пакеты `core/internal/...` нельзя импортировать из другого модуля Go. Поэтому каталог `core-overlay/` при сборке копируется во временную копию `third_party/lavray/core`, и код из него оказывается внутри модуля. Субмодуль и репозиторий `lavray` не изменяются. Тем же способом в копию попадает `core-overlay/inject/api` (экспортированный сеттер фабрики временных инстансов вместо reflect) и подменённая копия `modernc.org/libc`: на x86_64 SQLite вызывал устаревшие `open`/`stat`/`lstat`, которые seccomp Android убивает сигналом SIGSYS, и `core-overlay/libc-android` переписывает их в `*at`-вызовы (arm64 и arm не затронуты).

## Что поставлено в зависимость от измерений

Сетевой стек туннеля, MTU и настройки сборщика мусора Go выбраны по замерам из [MEASUREMENTS.md](MEASUREMENTS.md), а не по предположениям. Итог: стек `gvisor` (единственный рабочий, пока приложение исключено из своего VPN; выбора в настройках нет), MTU 9000, сборщик мусора с настройками по умолчанию.
